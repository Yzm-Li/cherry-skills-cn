# fanfic-adapt · 同人 OC 剧情合理化

一个给 **Cherry Studio 手机端** 用的 Skill：你带着 OC 主角和原作设定来，它帮你判断**剧情该怎么改、改到哪里、改了之后谁受影响**，而不是让 OC 一路开挂把原作踏平。

## 它解决什么

- OC 进入原作后，哪些剧情会变，哪些不会变？
- 改了一个节点，后面会连锁到什么程度？
- 原作角色为什么会接受/反对/利用 OC？
- OC 的能力会不会太强，把冲突写没？
- 怎么改才不像“作者亲妈”，又不把原作人物写 OOC？

## 包里有什么

```
fanfic-adapt/
├── SKILL.md                      # 核心：变量、基线、分叉点、涟漪、七问、输出
├── README.md                     # 本文件
├── references/
│   ├── oc-sheet.md               # OC 设定卡、能力/关系/信息审计
│   ├── canon-baseline.md         # 锚点、人物内核、世界规则、Canon/Fanon
│   ├── ripple-model.md           # 一/二/三阶影响、惯性、传播、时间
│   └── patterns.md               # 六种 OC 类型、三种改编规模、常见崩法
```

## 核心方法

1. **把 OC 设定变成变量**：只有能改变选择的设定才进剧情。
2. **建 Canon 基线**：5–8 个锚点、人物内核卡、世界规则、时间线。
3. **找最早接触点**：OC 第一次能影响原作的时间/地点/人物。
4. **推三阶涟漪**：直接事件 → 角色反应/阵营 → 组织/世界/终局。
5. **过高惯性关**：制度性事件不会因为 OC 出现就消失，只会换形式。
6. **过合理化七问**：动机、能力、机会、反应、代价、传播、主题。
7. **标改编规模**：轻改 / 中改 / 重改，默认中改的最小版本。

## 怎么装（Cherry Studio 手机端）

> 建议 0.4.0+；技能库从 0.2.1 开始提供。需要标准模式，模型支持工具调用。

### 方式 A：让 Cherry 自己创建（不用 GitHub）

1. 把 `SKILL.md` 发到手机。
2. 侧栏 **Skills（技能）** → 右上 **More（更多）** → **Create Skill（创建技能）**。
3. 把 `SKILL.md` 作为文本附件发过去，或粘贴正文。
4. 说：

   > 逐字读取附件里的 SKILL.md 正文，用 create_skill 创建一个名为 `fanfic-adapt` 的技能，description 用文件里的原文，正文不要改写，并绑定到我当前的 Agent。

5. 批准工具调用。
6. 到 **Agent 菜单 → 编辑 → 技能** 启用。

注意：只装 `SKILL.md`，`references/` 不会带上；核心流程都在主文件里。

### 方式 B：GitHub 安装（完整包，可更新）

1. 新建 public 仓库，上传整个 `fanfic-adapt/` 文件夹。
2. 复制文件夹链接，例如 `https://github.com/<你>/<repo>/tree/main/fanfic-adapt`。
3. App → **Skills → Discover（发现）** 粘贴链接；或在对话里说“安装这个技能：<链接>”并批准。
4. 到 Agent 编辑里启用。
5. 更新：技能详情 → **Update skill**。

### 方式 C：不安装

把 `SKILL.md` 去掉 frontmatter 的正文，粘进 Agent 的“指令 / 提示词”。零门槛，但占上下文、不能复用。

## 怎么用

先给三样东西：OC 设定、原作/时间线、你想改的节点。

- “OC 是 A 的旧友，能力是回退 10 秒但会失忆。原作第 12 话 A 被推下天台，帮我做中改方案。”
- “OC 穿进原作，只知道前 20 话。她不想改结局，只想救一个人，剧情怎么动？”
- “OC 站在反派阵营，但他和主角有旧情。别洗白，给我一个合理的立场冲突。”
- “这是我的 OC 卡和原作时间线，先告诉我哪些设定是无效设定。”
- “这个改编是不是太玛丽苏？按七问给我挑漏洞。”
- “把方案写成 8 章节拍，每章压力—选择—代价—新问题。”

调参：

| 你说 | 它会怎么调 |
| --- | --- |
| 轻改 / 别动主线 | 只改一个边缘节点，保留结局 |
| 中改 | 动一个关键节点，重推三阶后果 |
| 重改 / AU | 重写世界规则，明确标 AU |
| 只要方案 | 输出改编表，不写正文 |
| 要正文 | 按方案写场景，交 novel-prose 的文风规则 |
| 太玛丽苏 | 加代价、加失败、让出高光 |
| 反派太蠢 | 给反派情报、计划和反制 |
| OOC 了 | 回人物内核卡，改处境不改内核 |

## 一个最小示例

原作：A 在第 12 话被 B 推下天台。
OC：C，A 的旧友，能回退 10 秒，代价是偏头痛和丢失回退前的记忆。

- 分叉点：天台前 3 分钟。
- 一阶：C 回退，A 抓住栏杆，B 逃跑。
- 二阶：A 怀疑 C 怎么知道；B 派人查 C；C 不记得 B 的脸。
- 三阶：组织提前介入，原定第 20 话的清洗提前到第 16 话。
- 代价：C 暴露能力，被两方盯上；A 开始怕他。

不合理的写法：C 时停救 A，B 当场被抓，两人顺利在一起。没有代价，反派降智，后面所有冲突作废。

## 适合 / 不适合

适合：

- OC 插入、替换、关系型、穿越/重生、阵营对立
- 中长篇同人，需要重排时间线和人物反应
- 想让改编“有代价、有反作用”，不是纯爽文
- 需要检查 OOC、玛丽苏、反派降智

不适合：

- 只想写一段不改变任何事的日常糖（不需要改编模型）
- 完全原创、没有原作基线
- 需要替用户决定“拆不拆原作 CP”这类价值判断（可以分析，不替选）

## 局限

- 原作资料不全时，结论会受限于你给的信息；技能会标“待确认”，不假装知道。
- “合理”有口味差异：它保证因果和人物一致，不保证所有人都喜欢。
- 不复制原作长段原文；引用只做对照。
- 重改/AU 需要大量重建设定，不是一次输出就能完成。
