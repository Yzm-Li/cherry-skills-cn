# OC 设定卡与变量审计

## 一、OC 卡模板

```markdown
## 基本信息
- 名字：
- 年龄/身份：
- 进入原作的时间点：
- 站在哪个阵营：

## 能力
- 能做什么：
- 做不到什么：
- 代价/冷却/条件：
- 暴露后会怎样：

## 关系
- 与原作角色的既存关系：
- 为什么原作没提：
- 谁信任他/谁防着他：

## 信息
- 知道剧情吗？知道多少？
- 会记错什么？
- 谁不知道他知道？

## 目标
- 表面想要：
- 真正需要：
- 最怕：
- 底线：

## 弱点
- 性格缺陷：
- 能力盲区：
- 会误判什么：

## 声音
- 句长、用词、称呼、口头禅、禁语：
```

## 二、把设定变成变量

只有能改变选择的设定才进剧情。逐条问：

1. 它让 OC 能做到什么别人做不到的事？
2. 代价/限制是什么？
3. 谁会发现？发现后会发生什么？
4. 如果删掉这条设定，剧情会变吗？不会，就删。

### 模糊 vs 可用

| 模糊 | 可用 |
| --- | --- |
| “他很聪明” | “他能记住看过一遍的文件，但会忘记人名” |
| “她很强” | “她能在 3 秒内加速，之后 10 分钟手抖” |
| “他们关系很好” | “她替他挡过一次处分，从此他欠她一个人情” |
| “他知道剧情” | “他只看过前 20 话，后面只知道大概” |
| “他想改变结局” | “他只想救一个人，其他人他顾不过来” |

## 三、能力审计

| 问题 | 目的 |
| --- | --- |
| 能一招解决最终 boss 吗？ | 能，就必须加限制，否则故事结束 |
| 代价是什么？ | 没有代价的能力等于许愿 |
| 冷却/条件是什么？ | 决定他能不能连续使用 |
| 暴露后会怎样？ | 决定敌人和盟友的反应 |
| 谁能克制？ | 给对手留打法 |
| 他自己会误判吗？ | 给失败留空间 |

### 金手指四条

1. **有限**：有明确上限。
2. **有价**：每次使用都要付出。
3. **可见**：用多了会被发现。
4. **可反制**：对手能学会对付。

缺一条，冲突就会塌。

## 四、关系审计

画一张关系图：

```text
OC —— 信任 ——> A
OC —— 隐瞒 ——> B
OC <—— 利用 —— C
OC —— 旧怨 ——> D
```

每条关系问：

- 这段关系在原作时间线之前成立吗？
- 为什么原作没提？断联、隐瞒、失忆、时间差、还是不在场？
- 这段关系会改变谁的选择？
- 如果这段关系曝光，谁会受损？

## 五、信息审计

- OC 知道多少？全知、部分、还是只知道大概？
- 他的知识可靠吗？会不会记错、过时、被误导？
- 他说出来，谁信？谁不信？谁假装信？
- 他隐瞒，谁会发现？发现后怎么想？
- 蝴蝶效应之后，他的“剧情知识”什么时候开始失效？

信息型 OC 的看点不是“我知道”，是“我说了没人信/我记错了/我改变了未来，知识没用了”。

## 六、OC 不是许愿机

出现以下情况，说明 OC 压垮了故事：

- 所有难题都由他解决。
- 所有原作角色都围着他转。
- 他从不失败，失败也是别人的错。
- 他没有代价，或者代价只写在设定里，剧情里从不发生。
- 反派遇到他就降智。
- 原作的高光时刻都变成他的垫脚石。

修法：砍能力、加代价、让出高光、给对手一次赢、让他误判一次。

## 七、一页纸版本

如果用户只给一段话，至少补齐这六项再动笔：

1. 他想要什么？
2. 他能做什么，代价是什么？
3. 他什么时候、在哪里进入？
4. 他和谁有旧关系？
5. 他知道什么，会误判什么？
6. 他最大的弱点是什么？

## 八、同行模式再补四项

如果 OC 要一直跟在原作主角身边，再加：

1. **主角为什么留他**：不是“他想跟”，是主角主动邀请、默许、挽留、利用或监视。
2. **他补主角什么，主角补他什么**：互补要双向，不能只有 OC 有用。
3. **他的私目标**：主角不在场时，这条线也能推进。
4. **他什么时候会走**：退出条件写清楚，同行才不是“作者不让走”。

详见 `companion-mode.md`。
