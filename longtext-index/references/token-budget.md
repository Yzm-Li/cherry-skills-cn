# Token 预算与成本

## 一、估算

没有 tokenizer 时，用保守公式：

```text
tokens_est = (中文字符数 × 0.8 + 英文单词数 × 1.3 + 标点/数字 × 0.5) × 1.2
```

- 中文 1 字约 0.6–1 token，取 0.8 再乘 1.2，避免低估。
- 英文 1 词约 1.3 token。
- 代码、URL、数字更费 token，单独按 0.5–1 估。
- 有 tokenizer/usage 返回值时，用真实值覆盖估算，并记录偏差。

不要用“字数 ÷ 2”估算中文；会严重低估。

## 二、预算分配

设上下文窗口为 `W`：

| 用途 | 占比 | 说明 |
| --- | --- | --- |
| 输出预留 | 40% | 长答案、引用、结构化输出 |
| 系统/工具 | 10% | 系统提示、工具 schema |
| 全局简报/状态卡 | 5% | 人物、设定、术语、决议 |
| 索引切片 | 10% | L1 + L2 摘要 |
| 原文块 | 25% | 2–5 块 |
| 缓冲 | 10% | 重试、意外长结果 |

按窗口换算：

| W | 输出 | 系统 | 全局 | 索引 | 原文块 | 缓冲 |
| --- | --- | --- | --- | --- | --- | --- |
| 32k | 12.8k | 3.2k | 1.6k | 3.2k | 8k | 3.2k |
| 128k | 51.2k | 12.8k | 6.4k | 12.8k | 32k | 12.8k |
| 200k | 80k | 20k | 10k | 20k | 50k | 20k |
| 1M | 400k | 100k | 50k | 100k | 250k | 100k |

装不下时，先减原文块，再减索引；不要减输出预留。长答案分两次给，比截断好。

## 三、检索打分

```text
score =
  3 × 实体命中
+ 2 × 关键词命中
+ 2 × 标题/摘要相关
+ 1 × 与问题块相邻
- 1 × 已读过
- 2 × 与当前时间线冲突
```

取前 2–5 块；需要连续性时加前后各一块。总分低于阈值就停，不要为了“更全面”硬读。

### 停止条件

- 预算用完。
- 连续 2 块没有新增有效信息。
- 关键问题已被至少 2 块独立支持。
- 用户要的是定位，不是全貌。

## 四、成本模型

```text
全文直读成本 = Q × T
切片成本     = B + Q × (I + C + S + O)
```

- `Q`：问题数
- `T`：全文 token
- `B`：建索引一次性成本
- `I`：每次加载的索引 token
- `C`：每次加载的原文块 token
- `S`：状态卡 token
- `O`：输出 token

盈亏平衡点：

```text
Q* = B / (T - I - C - S - O)
```

例：`T=120k`，`B=8k`，`I=1k`，`C=6k`，`S=0.8k`，`O=1k`，则 `Q* ≈ 8k / 111.2k ≈ 0.07`。一次索引，几次提问就回本。

只问一次、文本又不算太大时，直接按章节读，不必建全套索引。

## 五、指标

每次任务结束，报告：

- 全文 token / 字数
- 实际加载 token / 字数
- 加载比例
- 使用块数 / 总块数
- 缓存命中块数
- 估算节省比例

```text
加载 5 / 96 块；约 9,800 / 186,400 字；约为全文 5.3%。
```

不要虚报节省；把建索引的成本也算进去，分“首次”和“后续”两次报告。

## 六、缓存的层级

| 层级 | 缓存什么 | 何时失效 |
| --- | --- | --- |
| 文件 | 文件哈希 | 文件内容变化 |
| 块 | 块哈希 | 块内容/边界变化 |
| 摘要 | 块摘要 | 块哈希变化 |
| 笔记 | 每块的结构化结果 | 块哈希或任务变化 |
| 答案 | 最终答案 | 相关块或问题变化 |

任务变了（摘要→一致性检查），笔记要重做，但摘要和索引可复用。

## 七、常见错误

| 错误 | 后果 | 修正 |
| --- | --- | --- |
| 中文按字数÷2 估 token | 上下文溢出 | 用 0.8×1.2 保守估 |
| 500 字以上原文重叠 | 重复付费 | 用摘要/状态卡代替 |
| 每块都重新总结全文 | 成本爆炸 | 层级摘要，只向上合并 |
| 为小文本建大索引 | 首轮更贵 | 8k 字以下直接读 |
| 索引写得太长 | 省不下 token | 索引 ≤ 全文 10% |
| 不预留输出 | 答案被截断 | 固定 40% 输出预算 |
| 读完不记录 | 中断重来 | state.json |
| 不报节省 | 无法验证 | 记录加载比例 |

## 八、压 token 的优先级

1. 不读无关块。
2. 用摘要代替原文。
3. 用状态卡代替上一块原文。
4. 只加邻居，不加整章。
5. 增量处理，不重做。
6. 限制输出长度。
7. 最后才考虑换更小的模型。
