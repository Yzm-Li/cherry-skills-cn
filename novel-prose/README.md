# novel-prose · 中文小说写作技能

一个给 **Cherry Studio 手机端** 用的中文小说写作 Skill：让行文更流畅、幽默更自然、描写更细，双人与多人对话不打架，同时压掉 AI 味。

## 先说清楚：这不是 MCP 插件

Cherry Studio 手机端“插件”页里的 GitHub、高德、飞书、企业微信，是**编译进 App 的内置 MCP 连接器**，官方文档明确说“这是 bundled code registration，不是下载安装的可执行插件”。第三方目前不能往 App 里塞一个代码插件。

手机端真正可安装、可复用的扩展叫 **Skill（技能）**：一个 `SKILL.md` 指令包，安装后绑定到 Agent，按需加载。它不加工具、不加权限，只提供写作方法——正好是“文风”这类需求该用的形态。

> 参考：Cherry Mobile 的 [Agent Skills 文档](https://github.com/CherryHQ/cherry-studio-app/blob/main/docs/references/agent/agent-skills.md)、[内置 MCP 插件说明](https://github.com/CherryHQ/cherry-studio-app/blob/main/docs/references/agent/built-in-mcp-design.md)。

## v1.3 改了什么

- **自己选人数**：用户指定就照办；没指定，按场景功能选，默认“能产生压力的最小人数”。双人管私密对峙，三人管见证/挑拨，四人以上管会议/宴席/庭审/群像。
- **多人调度**：先定空间（谁坐哪、谁靠门），再定阵营（谁和谁一伙、谁可能倒戈），再定议程（这场必须解决什么）。
- **发言权**：主角 40%、对手 30%、第三方 20%、其余 10%；同时主导不超过三个，其余用动作、短句或沉默参与。
- **沉默者**：不说话的要有戏；沉默者一开口，必须改变局面。
- **三种阵型**：一对多（围攻/审判）、二对二（谈判/家族）、三角（引荐/挑拨/摊牌）。
- **可读性**：多人场景该用名字就用名字；一次只写清一条线；旁观者反应只写两三个。
- **调档**：新增“只要双人”“多人戏太乱”“多人像开会”三条口令。

详细调度、六种阵型和四人家族饭桌示例见 [group-scenes.md](references/group-scenes.md)。

## v1.2 改了什么

- **音步与句读**：汉语是二音节一步。优先“治疗疾病”而不是“治疗病”；四字格是两个二音步；长短句读交替；句尾别落在虚字上。
- **潜台词**：写对话前先给每个角色写一句“他真正想说的”。四种落地：答非所问、转移话题、过度礼貌、动作代替回答。
- **自由间接引语**：第三人称限知的高级写法，去掉“他想”，把念头嵌进叙述；附三条边界，防止跳人。
- **开场**：三种开场，第一段只给一个非知道不可的问题；不写天气和背景。
- **信息差**：读者知道、人物知道、谁都不知道，三种给法对应紧张、悬念、谜。
- **自检**：从 8 项扩到 10 项，加入音步、潜台词和视角一致性。

## v1.1 改了什么

这一版把“凭感觉写好”换成了可检查的规则：

- **中文生态**：弱动词 + 抽象名词、抽象名词作主语、“们 / 之一 / 由于 / 成功地”、被动句、“的”字链，逐条对照余光中《中文的常态与变态》的病类。
- **场景引擎**：目标 → 冲突 → 挫折；反应 → 困境 → 决定。反应链按“生理 → 动作 → 想法 → 对话”排，避免“聊了半天，什么都没发生”。
- **细节落地**：动态造型、简笔勾勒、道具出现三次、详略对比、侧面反应。不是形容词多，是动作准。
- **幽默**：三番四抖、回调、不一致 / 释放 / 优越感，要求具体化和留白。
- **AI 味**：不只查黑名单，还查句长分布、模板过渡、空洞总结和信息增量。

## 安装：三选一

> 完整步骤（含 App 下载、版本要求、绑定与排错）见 [INSTALL.md](INSTALL.md)。手机端建议 0.4.0+；技能库从 0.2.1 开始提供。

### 方式 A：让 Cherry 自己创建（最快，不用 GitHub）

1. 打开 Cherry Studio 手机端 → 侧栏 **Skills（技能）** → 右上 **More（更多）** → **Create Skill（创建技能）**。
2. 把 `SKILL.md` 的正文（第二个 `---` 之后的部分）粘贴到对话里，或作为文本附件发给 Agent。
3. 补一句：

   > 逐字读取上面的内容，用 create_skill 创建一个名为 `novel-prose` 的技能，描述用文件里的 description，正文用原文，并绑定到我当前的小说助手。

4. 批准工具调用；安装完成后，到 Agent 设置里确认该技能已启用。

注意：`create_skill` 只生成一个 `SKILL.md`，`references/` 不会一起安装。核心规则都在 `SKILL.md` 里，日常够用；想要完整包用方式 B。

### 方式 B：GitHub 安装（完整包，可更新）

1. 新建一个 **public** 仓库。
2. 把整个 `novel-prose/` 文件夹上传，保持目录名与 `name` 一致。
3. 复制文件夹链接，例如：

   ```
   https://github.com/<你的用户名>/<仓库名>/tree/main/novel-prose
   ```

4. Cherry Studio 手机端 → **Skills（技能）** → **发现 / Discover** → 在搜索框粘贴链接 → 选中 `novel-prose` → 安装。
5. 安装只进技能库，不会自动绑定。到 Agent 设置里打开这个技能，或在对话输入框 **+ → Skills** 里显式选择。

支持仓库根目录、子目录、`SKILL.md` 直链。以后更新时重新粘贴同一链接即可，会跟随原 ref 拉取新版本。

### 方式 C：不安装，直接当 Agent 指令

把 `SKILL.md` 去掉 frontmatter 的正文，粘贴进 Agent 的“指令 / 提示词”，保存。

优点：零门槛。缺点：占上下文、不能复用、不能更新，也不会有 `references/` 的按需读取。

### 已经装过旧版怎么更新

- GitHub 安装的：技能详情页点 **Update skill**，会跟随原链接拉新版。
- `create_skill` 创建的：同名不能覆盖。先卸载旧技能，再按方式 A 重建；或者改用方式 B，以后就能一键更新。

## 怎么用

绑定后，在对话里直接说，或在输入框 **+ → Skills** 里选它：

- “用 novel-prose 续写这段，接住语气，别总结。”
- “把这段改得幽默一点，冷幽默，不要段子。”
- “这场戏再细一点，五感只留三种，结尾停在动作上。”
- “写一场四人饭桌戏：父亲、母亲、哥哥、弟弟，不要轮流发言。”
- “这场改成双人对峙，第三个人只在结尾进来。”
- “三人谈判，谁先倒戈？别让第三个人只当旁听。”
- “太拖了，快一点，删环境描写。”
- “AI 味重，按黑名单过一遍。”

调档口令：

| 你说 | 它会怎么调 |
| --- | --- |
| 再幽默点 / 太干了 | 幽默档 +1，加错位对话与冷叙述 |
| 太贫了 / 收一收 | 幽默档 -1，删解释性笑点 |
| 再细一点 / 要画面感 | 细节档 +1，加五感与动作分解 |
| 太拖了 / 快点 | 细节档 -1，删环境与心理 |
| 像流水账 | 加场景目标与阻力，每场必须有变化 |
| AI 味重 | 按黑名单逐条替换，删总结句，查句长 |
| 翻译腔重 | 改弱动词、被动句、抽象名词主语，再删“的”字链 |
| 只要双人 | 删到两个视角人物，第三人改成电话/来信/不在场 |
| 多人戏太乱 | 砍到三个主导发言人，其余用动作；明确空间和阵营 |
| 多人像开会 | 给每个人一个私心，加打断、抢话、侧聊，删程序性发言 |

## 它为什么可能有用

- 不给“请写得生动流畅”这种空话，只给可执行规则：拆句、删连接词、一段一个功能、笑点三拍、五感选三种。
- 有中文生态检查：不只删“仿佛”，还治“作出贡献、进行研究、由于……使得、被……所”这类翻译腔。
- 有音步检查：读出声，听“治疗病”这种跛脚节奏，句尾别落在虚字上。
- 有对话潜台词：先写“他真正想说的”，再让角色答非所问、转移话题或用动作回答。
- 有视角工具：限知、自由间接引语，贴近人物又不写“他想”。
- 有群像调度：先选人数，再定空间、阵营、议程；只让三个主导发言，沉默者也有戏。
- 有场景引擎：每场戏问目标、冲突、变化；没有变化就合并，专治流水账。
- 有自检：交付前过一遍流畅、场景、幽默、细节、一致性，不把检查表丢给读者。
- 改稿分轻、中、重三档，不会一上来把作者的原声洗掉。
- 有档位：同一套规则能写冷幽默都市，也能写零幽默的悲剧，不会所有场景一个腔调。

## 局限

- 上限由模型决定。规则能减少坏习惯，不能把弱模型变成好作家。
- Skill 不保存你的设定。长篇请自建设定文档，每场戏把相关事实贴进对话。
- 长篇会风格漂移。重要章节建议一次写一场戏，写完立刻按 `revision-checklist.md` 过一遍。
