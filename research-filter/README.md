# research-filter · 联网信息降噪技能

一个给 **Cherry Studio 手机端** 用的 Skill：把网上搜到的一堆东西，筛掉噪声、去掉重复、核过来源，再整理成**有序、详细、能直接拿去做决定**的中文报告。

不是“多搜几个链接”，而是“少给结论，多给证据；少堆信息，多给结构”。

## 包里有什么

```
research-filter/
├── SKILL.md                      # 核心：搜索、降噪、抽取、核验、成稿
├── README.md                     # 本文件
├── references/
│   ├── source-triage.md          # 噪声类型、来源分级、评分卡
│   ├── verification.md           # 主张台账、数字/引语核对、冲突处理
│   ├── output-templates.md       # 快报/标准/深度、对比表、时间线
│   └── examples.md               # 从噪声到成稿的完整示例
```

`SKILL.md` 可独立使用；`references/` 是加餐。

## 它怎么“降噪”

1. **先铺开再收口**：3–6 组查询，中英文、官方/媒体/社区三条线，不靠一个关键词搜到底。
2. **硬淘汰 + 软标记**：无源截图、SEO 站群、AI 洗稿、通稿转载直接扔；单一匿名源、论坛体验、厂商自述保留但降权。
3. **六维评分**：权威、一手、证据、时效、独立、透明，每项 0–2 分；低分只当线索。
4. **两源规则**：关键结论要一个原始来源，或两个真正独立的来源；十篇转载算一个。
5. **冲突不平均**：并列呈现，解释口径差异；不知道就写不知道。
6. **按主题成稿**：先结论，再关键发现，再证据表，再细节；不按“我搜了什么”组织。

## 输出长什么样

默认是标准报告（800–1500 字）：

```markdown
**结论**：一句话回答。
## 关键发现
1. 判断 + 证据 [1]
2. 判断 + 证据 [2]
## 证据表
| 主张 | 证据 | 来源 | 日期 | 置信度 |
## 详细展开
### 主题一……
## 矛盾、空白与风险
## 来源
## 下一步
```

也可以要：

- **快报**：300–500 字，5 条发现
- **深度档案**：2000 字以上，加方法、时间线、利益地图、情景推演
- **对比表 / 时间线 / 决策矩阵**：按任务选

## 怎么装（Cherry Studio 手机端）

> 手机端建议 0.4.0+；技能库从 0.2.1 开始提供。需要标准模式，模型要支持工具调用。

### 方式 A：让 Cherry 自己创建（不用 GitHub）

1. 把 `SKILL.md` 发到手机（微信文件传输、AirDrop、网盘）。
2. 打开侧栏 **Skills（技能）** → 右上 **More（更多）** → **Create Skill（创建技能）**。
3. 把 `SKILL.md` 作为文本附件发过去，或粘贴正文（第二个 `---` 之后）。
4. 说：

   > 逐字读取附件里的 SKILL.md 正文，用 create_skill 创建一个名为 `research-filter` 的技能，description 用文件里的原文，正文不要改写，并绑定到我当前的 Agent。

5. 批准工具调用。
6. 到 **Agent 菜单 → 编辑 → 技能** 启用。

注意：只装 `SKILL.md`，`references/` 不会带上；核心流程都在主文件里。

### 方式 B：GitHub 安装（完整包，可更新）

1. 新建 public 仓库，上传整个 `research-filter/` 文件夹。
2. 复制文件夹链接，例如 `https://github.com/<你>/<repo>/tree/main/research-filter`。
3. App → **Skills → Discover（发现）** 粘贴链接；或在对话里说“安装这个技能：<链接>”并批准。
4. 到 Agent 编辑里启用。
5. 更新：技能详情 → **Update skill**。

### 方式 C：不安装

把 `SKILL.md` 去掉 frontmatter 的正文，粘进 Agent 的“指令 / 提示词”。零门槛，但占上下文、不能复用。

## 怎么用

装好后直接说：

- “用 research-filter 查一下：2026 年国内便携储能市场，谁在打价格战，证据是什么。”
- “对比三款 1000Wh 便携电源，按重量、真实容量、价格、售后排，标出未知项。”
- “网上说某公司裁员 30%，帮我核一下，别给我营销号。”
- “把这篇长文和它的引用源整理成一页纸，保留数字和日期。”
- “我只要快报，300 字，三条发现，两个来源。”

调参：

| 你说 | 它会怎么调 |
| --- | --- |
| 快一点 / 只要结论 | 快报，300–500 字 |
| 详细点 / 做深 | 深度档案，加方法和时间线 |
| 要有出处 | 每个判断带 `[n]`，文末来源分级 |
| 别堆链接 | 每条来源在正文里有用途，删无用途链接 |
| 只要一手 | 优先官方/论文/财报，二手只做背景 |
| 找反面 | 主动搜“问题、争议、失败、诉讼、召回” |

## 设计取舍

- **宁缺毋滥**：一个硬结论，胜过十条模糊信息。
- **可追溯**：每个关键判断都能回到一个日期和一条链接。
- **可行动**：最后给“下一步”，不只给“情况很复杂”。
- **敢写未知**：搜不到就说搜不到，不拿推测填坑。
- **不绕过边界**：付费墙、登录墙、隐私内容，说明限制，不硬闯。

## 局限

- 依赖当前会话的搜索/抓取工具；工具不可用时只能用手头资料。
- 付费报告、内部数据、被删除的页面，可能拿不到原文。
- 搜索工具返回摘要时，只能标“仅见摘要”，不能假装读过全文。
- 它提高的是“信息卫生”，不保证结论一定正确；重要决定仍要人复核。
