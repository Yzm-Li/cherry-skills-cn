# 来源分级与噪声识别

## 一、六个快速问题

拿到一个页面，先问：

1. 谁写的？有没有署名、机构、利益关系？
2. 什么时候写的？事件发生时间和发布时间是不是一回事？
3. 原始材料在哪？它引用了谁？
4. 有没有数据、方法、样本、口径？
5. 它是在报道事实，还是在表达观点、带货、公关？
6. 如果它错了，谁会受益？

六问里有两问答不上来，就降到“线索”，不要当证据。

## 二、常见噪声类型

| 类型 | 特征 | 处理 |
| --- | --- | --- |
| 无源截图 | 聊天记录、朋友圈、X 截图，没有原帖链接 | 找原帖；找不到就淘汰 |
| “据悉/网传” | 全文没有一个具名来源 | 当传言，除非研究传言本身 |
| 旧闻新发 | 旧事件换新日期；内容与日期矛盾 | 搜最早发布日期 |
| 洗稿拼接 | 多篇文章段落拼接，语句不通，来源互相矛盾 | 找原始出处 |
| SEO 站群 | 同一模板批量生成，标题夸张，正文空 | 淘汰 |
| AI 内容农场 | 结构工整、没有具体人名地名、无原始链接 | 淘汰或只当关键词线索 |
| 软文/赞助 | 通篇好评，没有缺点，购买链接显眼 | 标注“商业内容” |
| 伪评测 | 没有测试环境、没有数据、只有感受 | 降权 |
| 通稿转载 | 十家媒体同一时间同一措辞 | 算一个来源 |
| 预印本 | 未经同行评议 | 标注，不作定论 |
| 厂商 benchmark | 只测对自己有利的场景 | 标注“厂商称” |
| 机器翻译 | 术语错、语句怪、来源不明 | 找原文 |

## 三、来源层级

### T1：原始材料

- 官方公告、政策原文、监管文件
- 财报、招股书、投资者关系材料
- 法院文书、合同、专利
- 论文原文、数据集、技术文档
- 亲历者的一手记录（日记、邮件、工单）

用途：事实依据。注意：官方也会选择性披露，仍要看口径。

### T2：有编辑规范的第二手

- 主流媒体、通讯社
- 行业协会、研究机构
- 有审稿/更正机制的专业媒体

用途：交叉验证、背景、解释。注意：可能引用同一通稿。

### T3：垂直与个人

- 垂直媒体、专业博客
- 从业者长文、技术社区
- 用户论坛、评价区

用途：找线索、找解释、找“真实体验”。注意：不能从“有人这样说”推到“普遍如此”。

### T4：聚合与匿名

- 聚合站、导航站
- SEO 内容、AI 生成站
- 匿名爆料、无源转载

用途：只当关键词线索。不要作为关键证据。

## 四、独立性测试

两个来源算不算独立，看三点：

1. 它们有没有引用同一篇通稿/同一个匿名信源？
2. 它们的作者/机构有没有共同利益？
3. 它们的数字是不是完全一样、措辞也一样？

三点中有一项中招，就按一个来源算。

## 五、评分示例

假设三个来源都说“某产品销量第一”：

- A：厂商官网新闻稿，无数据来源 → 权威 1、一手 1、证据 1、时效 2、独立 0、透明 1 = 6（可用但标注“厂商称”）
- B：行业报告，注明样本与方法，但报告由厂商赞助 → 权威 2、一手 2、证据 2、时效 2、独立 0、透明 2 = 10（数据可用，结论降权）
- C：地方小报转载 A，无署名 → 权威 0、一手 0、证据 0、时效 1、独立 0、透明 0 = 1（淘汰）

结论不能写“销量第一”，只能写“厂商称销量第一；一份厂商赞助的行业报告给出相近数据；无独立第三方验证”。

## 六、追原始来源

1. 从引用链接、脚注、文中“据……报道”找上游。
2. 搜标题 + 作者 + 机构，找最早版本。
3. 用日期排序，找事件发生当天的报道。
4. 找原始文件：公告、PDF、数据集、视频、庭审记录。
5. 找不到上游，就在文中写“转述，未找到原始来源”。

## 七、红旗清单

- 标题里有“震惊、炸裂、彻底改变、史上最强”。
- 全文没有一个人名、机构名、日期。
- 数字很整，且没有单位、样本、口径。
- 只讲成功，不讲失败、成本、限制。
- 文末直接带货或引导加微信。
- 同一段话在多个网站一字不差出现。
- 图片是拼接的、带别的网站水印。
- “内部人士”没有名字，也没有可验证的细节。
