# scene-forge · 场景条件对比与最优场景

一个给 **Cherry Studio 手机端** 用的 Skill：先列全场景条件，再生成多个不同“冲突引擎”的候选，按冲突、代价、主动性、转折、因果、主题打分，**自己选出最合适的一个**，写成节拍或正文。

不是“给几个点子让你挑”，是“比完所有条件，直接选一个最能打的”。

## 它解决什么

- 这场戏怎么写才不水？
- 人物到了这个地点，该发生什么？
- 几个场景方案，哪个冲突最强、最像这个人会做的事？
- 想让剧情更抓人，但不想靠吵架、误会、降智反派。
- 改稿发现某场没有变化，怎么换引擎重写？

## 包里有什么

```
scene-forge/
├── SKILL.md                      # 核心：条件、候选、评分、选择、节拍
├── README.md                     # 本文件
├── references/
│   ├── scene-engines.md          # 12 种冲突引擎与崩法
│   ├── constraints.md            # 硬/软条件清单
│   ├── scoring.md                # 八维评分、权重、致命缺陷
│   └── beats.md                  # 八拍、短场景、动作、群像、揭露
```

## 核心流程

1. **收条件**：canon、人物、时间、空间、视角、剧情任务、分级；软条件包括类型、基调、节奏、读者、主题、篇幅。
2. **生成 3–5 个候选**：换冲突引擎，不是换地点。争夺、审讯、谈判、救援、揭露、背叛、仪式、围困等。
3. **先过硬条件**：违反 canon/人物能力/时间线的直接淘汰。
4. **八维打分**：冲突 25、代价 20、主动 15、转折 15、因果 10、主题 10、新鲜 5、可行 5。
5. **自己选**：最高分；前两名差 5 分内，选代价更不可逆的；低于 60 分重新生成，不凑合。
6. **写节拍**：进入 → 触发 → 尝试 → 升级 → 转折 → 危机选择 → 代价 → 离场钩子。
7. **写正文**：交给 `novel-prose` 的文风规则；本技能负责“这场戏为什么成立”。

## 怎么装

### GitHub 安装（推荐）

把你的 `scene-forge/` 文件夹上传到 `cherry-skills-cn` 仓库根目录，然后：

```text
https://github.com/Yzm-Li/cherry-skills-cn/tree/main/scene-forge
```

手机端：**Skills → Discover** → 粘贴链接 → 安装 → 到 **Agent 编辑 → 技能** 启用。

如果文件夹链接解析失败，用：

```text
https://raw.githubusercontent.com/Yzm-Li/cherry-skills-cn/main/scene-forge/SKILL.md
```

### Create Skill（不用 GitHub）

1. 把 `SKILL.md` 发到手机。
2. **Skills → More → Create Skill**。
3. 把 `SKILL.md` 作为附件发过去，说：

   > 逐字读取附件里的 SKILL.md 正文，用 create_skill 创建一个名为 `scene-forge` 的技能，description 用文件里的原文，正文不要改写，并绑定到我当前的 Agent。

注意：这条路只装 `SKILL.md`，`references/` 不会带上；核心流程都在主文件里。

## 怎么用

给它故事背景 + 这场戏要完成什么：

- “第 12 章，林晚要在晚宴上从周野手里拿到救弟弟的钥匙。她不能暴露身份，周野多疑，弟弟在楼上。帮我设计这场戏，要紧张。”
- “这场戏太平了：两个人坐在咖啡馆聊天。给我换三个不同引擎，选最合适的。”
- “这几个场景哪个更好：偷钥匙 / 当众揭发 / 用秘密交易 / 制造火警？按冲突、代价、主动性打分。”
- “我只想要节拍，不写正文。”
- “这场是群像饭桌，四个人，别写成轮流发言。”
- “要黑色幽默，但别消解危险。”

调参：

| 你说 | 它会怎么调 |
| --- | --- |
| 更冲突 | 提高代价、缩短时间、减少选项 |
| 更意外 | 加一个公平转折，但不为反转而反转 |
| 更安静 | 换揭露/告别/谈判引擎，用潜台词 |
| 更抓人 | 开场给具体问题，结尾留钩子 |
| 只要方案 | 输出候选对比 + 选择理由，不写正文 |
| 只要正文 | 直接按选定方案写，节拍内部执行 |
| 别加新设定 | 只在现有角色/地点/道具里选 |

## 一个最小示例

**任务**：林晚要在晚宴上从周野手里拿到救弟弟的钥匙。

- A 偷钥匙：潜入书房，趁他换衣服。
- B 当众揭发：用宾客压力逼他交人。
- C 交易：用她知道的一个秘密换钥匙。
- D 制造火警：趁乱下手。

评分后选 **C**，混合 B 的一拍：交易到一半，有宾客认出林晚，迫使她当场加价。

结果：她必须在“救弟弟”和“保住身份”之间选，选完两样都损失。A 只是偷东西，B 只是闹大，D 靠巧合。

## 它为什么可能有用

- 不靠“多写冲突”这种空话，直接给冲突引擎和升级阶梯。
- 不把选择题丢给用户：先比条件，再选一个。
- 评分逼你回答：代价是什么、主角主动吗、转折公平吗。
- 允许安静场景：谈判、揭露、告别也是冲突，不是只有打架。
- 和 `novel-prose` 分工：它管“写得好”，本技能管“这场戏值不值得写、该写哪一个”。

## 局限

- 条件给得越少，默认假设越多；关键 canon 缺失时结论会偏。
- 评分是排除坏方案的工具，不是文学裁判；最终还要看前后文。
- 它不替用户决定重大剧情（死亡、背叛、拆 CP），只给方案和代价。
- 需要新增设定时，会标“假设”，不会偷偷改 canon。
